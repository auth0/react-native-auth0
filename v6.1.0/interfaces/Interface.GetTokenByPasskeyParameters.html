    Interface GetTokenByPasskeyParameters

    Parameters for exchanging a passkey credential response for Auth0 tokens.

    After the platform credential manager returns the credential (either a new registration or an assertion), pass the auth_session and the credential response to this method to obtain Auth0 tokens.

    See

    https://auth0.com/docs/authenticate/database-connections/passkeys

    Optionalverification

    verification?: Record<string, string>

    The one-time codes the user entered, keyed by the identifier each code was sent to (for example { email: '123456', phone: '654321' }).

    Only meaningful when the database connection requires identifier verification, that is, when the signup challenge returned PasskeyChallengeResponse.verificationRequired: provide a code for each of those identifiers. Omitting it is always valid.

    Only codes for identifiers this SDK knows about (email, phone) are sent; others are ignored. A code that is empty or only whitespace rejects with a PasskeyError of type PASSKEY_INVALID_PARAMETER on every platform, before anything is sent.

    If a code is wrong while the session is still alive, the call rejects with a PasskeyError of type PASSKEY_VERIFICATION_RETRYABLE. To retry, read error.getVerificationRetryPayload() and call getTokenByPasskey again with:

    • the same authResponse, so the user does not create a second passkey;
    • its authSession (the same, still valid session);
    • its verificationRequired (only the identifiers whose code was wrong; if it is undefined, those of the challenge) as verificationRequired;
    • fresh codes for those identifiers only as verification. The other identifiers are already verified in this session.

    Only used when completing a passkey signup.

    • Defined in types/parameters.ts:657

    OptionalverificationRequired

    verificationRequired?: string[]

    The identifiers the codes in verification are for: on the first attempt, PasskeyChallengeResponse.verificationRequired from the signup challenge; on a retry, verificationRequired from PasskeyError.getVerificationRetryPayload() (see verification).

    Only meaningful when the database connection requires identifier verification. Omitting it is always valid: pass it only when the challenge or the retry payload has one.

    iOS and Android: passed to Auth0.swift / Auth0.Android, which check, before sending anything, that every listed identifier has a code in verification. If one has none, the call rejects with a PasskeyError of type PASSKEY_EXCHANGE_FAILED, and the session stays usable. When omitted, nothing is checked.

    Web: ignored (auth0-spa-js does not take it). A missing code is sent to Auth0 as is, and also rejects with PASSKEY_EXCHANGE_FAILED.

    Identifiers this SDK does not know about (other than email, phone) are ignored. Only used when completing a passkey signup.
